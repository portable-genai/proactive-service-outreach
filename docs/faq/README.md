# FAQ

Five pages, one per audience, each answering the questions that audience actually asks in a
review. They are written to be handed over, so they name the file that is the evidence rather
than describing a control in the abstract.

| Page | Who asks | The one question it turns on |
|---|---|---|
| [security.md](security.md) | second line, security architecture | what stops this contacting the wrong person? |
| [compliance.md](compliance.md) | compliance, conduct, privacy | how do you prove consent for a message you sent nine months ago? |
| [features.md](features.md) | the business owner | what does it actually do, and what will it refuse to do? |
| [portability.md](portability.md) | procurement, sovereignty review | how do we leave? |
| [adoption.md](adoption.md) | the engineering team taking it on | what do we have to supply? |

Authority order for anything these pages disagree with: `SPEC.md`, then `ARCHITECTURE.md`, then
`COMPLIANCE.md`, then `README.md`. These pages restate; they do not decide.
