# COMPLIANCE: Proactive Service Outreach (E5)

Maps every catalog principle (P-01 to P-13) and every platform dependency rule (R1 to R8) to a
control in THIS repo, with the file that is the evidence. Aligned to MAS TRM, APRA CPS 234 and
CPS 230, HKMA and PDPA-class regimes; the regulatory crosswalk itself is adopter-owned (see the
last section).

## How to read the status column

| Status | Meaning |
|---|---|
| **Covered** | The control exists in this repo and a test fails the build if it regresses. |
| **Partial** | The in-repo half exists; the named deploy-time or platform half does not yet. |
| **TODO (repo owner)** | NOT covered. The row names exactly what this repo must add. A rendered repo starts here on several rows by design, because the control depends on the vertical or on the deployment, and claiming it before it exists would be worse than owing it. |
| **n/a** | The principle does not apply to what this service does. State WHY, and revisit if the scope changes. |

A rendered repo is honest on day one, not complete on day one. Close the TODO rows before this
document is cited as evidence to a second or third line of defence.

## Principles

| Principle | Status | Control and evidence in this repo |
|---|---|---|
| **P-01** Hybrid on-prem plus GCP (Interconnect, VPC-SC) | Partial | The `onprem` adapter family is a real, bound profile, so a system of record can stay on premises while this service bursts to the managed profile: `src/proactive_outreach/adapters/onprem/`. The perimeter now exists: `infra/terraform/vpc_sc.tf` draws a VPC Service Controls boundary around exactly the APIs this stack uses, starting in DRY RUN behind `vpc_sc_enforce` so nothing is enforced blind on a path nobody has watched, and `production_edge.tf` gives the Cloud Run service load-balancer-only ingress. TODO (repo owner): the Interconnect attachment and the private-egress network (a VPC connector or Private Service Connect, plus the egress rule that reaches the `marketing-compliance-gate` consent store and the `human-review-console` and nothing else). A service that can reach the open internet can be told to contact somebody through it, so that rule is load-bearing here; both halves depend on the adopter's own network. |
| **P-02** No vendor lock-in (ports and adapters) | Covered | Every boundary is a `@runtime_checkable` Protocol in `ports/`, bound per profile from `config/settings.yaml`. `tests/contract/test_port_parity.py` proves every port binds in every profile with the cloud SDKs unimportable; `tests/contract/test_behavioral_parity.py` proves the same request behaves the same at each family's boundary. Exit path: `docs/onprem-migration.md`. |
| **P-03** Single region by default (residency) | Covered | The region is chosen once (`asia-southeast1`), carried by `config/settings.yaml`, reported by `/healthz` and printed on the agent card, and it is now ENFORCED at deploy time rather than described: `infra/terraform/variables.tf` validates the region against the residency allowlist at plan, `org_policy.tf` pins `gcp.resourceLocations` to that region's location group, and every regional resource (the CMEK key ring, the WORM log bucket, the synthesised-audio bucket and the Cloud Run service) is created in it. `OUTREACH_SPEECH_OUTPUT_URI` is deliberately not a variable: the stack sets it from the bucket it created, because an operator who could name the destination could name an out-of-region one. `infra/terraform/production_edge.tftest.hcl` is the standing gate: `reject_region_outside_the_residency_allowlist` fails if the allowlist stops refusing, and `residency_defaults_are_in_country` fails if any of those resources drifts off region. It runs with a mocked provider, so `make tf-check` proves it with no project and no credentials. The one location this stack cannot pin is the client-owned event view, which lives in the client's project; `docs/runbook.md` says so rather than implying otherwise. |
| **P-04** Minimise data to the model | Covered | The model is handed a CLOSED FACT SET and nothing else: not the event, not the free text, not the subject id, not the consent decision (`domain/drafting.py`, `domain/trigger_engine.py`, which drops every attribute a rule does not require). Redaction then happens before every boundary, not once: before the audit write (`domain/outreach_service.py`), before the review payload leaves the process (`adapters/_review_payload.py`, against EVERY jurisdiction's rows because the console is a shared sink), and before a tool result can enter a model's context (`agent/tools.py`). `tests/unit/test_not_falsely_green.py` proves the safety metric can go red. |
| **P-05** Grounding over fine-tuning | Covered for what this service generates | The only generated text is a notification body, and it is grounded in the EVENT rather than in a corpus: `domain/drafting.py` rejects any digit run absent from the event's facts, any missing required fact, any banned phrase and any personal data, and a rejected draft is discarded rather than repaired. There is deliberately no retrieval port, because there is nothing to retrieve: a service notification quotes the operational event and nothing else. Rule R3 is therefore n/a here, not owed. Never fine-tune on personal data. |
| **P-06** Human in the loop, maker-checker | Covered | A consequential band sets `requires_human_review` AND routes the result to the human-review console in the same request (`api/app.py`, `cli/main.py`, `agent/tools.py`). CRITICAL demands two approvals (`adapters/_review_payload.py`). `tests/unit/test_review_routing.py` asserts the routing, not the flag. |
| **P-07** Auditable and explainable by design | Covered | Append-only, hash-chained WORM audit log with an external head anchor for tail truncation (`adapters/local/audit.py`, `tests/unit/test_audit_anchor.py`); every result carries a `Citation`, including the policy rows it applied and the consent decision id; the audit actor is the verified principal, never the request body. REFUSALS are audited as fully as sends, because "why was this person NOT told" is the question asked after an incident. The managed profile writes the same already-redacted records to a Cloud Logging bucket whose retention is LOCKED, so they cannot be altered or deleted for the retention window (`infra/terraform/logging_worm.tf`), and DATA_READ audit logging is enabled there, so a read of the evidence is itself recorded. TODO (repo owner): a model card for whichever model the managed drafter is pointed at. |
| **P-08** Eval-gated promotion | Partial | `eval/run_eval.py --mode smoke` runs in the offline gate on every change; `--mode gate` delegates the promotion verdict to `model-quality-gate` and refuses to run off the managed profile. TODO (repo owner): register this repo's metric bundle and thresholds with `model-quality-gate`, so gate mode has an authority to ask. |
| **P-09** Defence in depth, zero trust | Partial | Server-verified identity with the client-asserted actor discarded, fail-closed S2S authentication, CORS that never becomes `*`, security headers, and an app-object loopback exposure guard whose posture is derived from the identity BINDING (the adapter declares whether it can verify an end user at all) and never from a service credential, so setting the S2S token cannot unbound the end-user routes (`api/app.py`, `ports/identity.py`, `tests/unit/test_serving_path_exposure.py`, `tests/unit/test_end_user_auth_posture.py`). The deploy-time half is now in place: one regional CMEK key with an explicit binding for EACH service agent that encrypts under it, because encryption does not cascade (`infra/terraform/kms.tf`); one least-privilege serving identity holding only the roles a request needs, with exportable service-account keys forbidden by org policy rather than merely avoided (`iam.tf`, `org_policy.tf`), and with write-only access to the audio bucket so the recording of what a customer was told cannot be replaced afterwards by the credential that sent it (`storage.tf`); and an edge that admits nobody by default, with IAP in front of the backend service and a Cloud Armor per-source throttle (`production_edge.tf`). TODO (repo owner): private endpoints, meaning Private Service Connect or a VPC connector with the egress rule that reaches the consent store and the review console and nothing else; and a distinct agent identity, which this stack deliberately does not create while the agent tools run inside the API process and it would have nothing to attach to. |
| **P-10** Resilience and graceful degradation | Partial | Every outbound dependency degrades in the SAFE direction, which for this vertical means fewer messages and never more: an unreachable consent store denies (`domain/outreach_service.py`), an unreachable drafter holds the notification for a human (`domain/drafting.py` fallback plus `requires_human_review`), an unreachable review console retains the item in the outbox, and an unreachable speech channel reports an undelivered notification rather than a delivered one. TODO (repo owner): timeouts and a circuit breaker per dependency, a documented kill switch, and the CPS 230 recovery objectives in `docs/runbook.md`. |
| **P-11** Cost and latency control | Partial | The largest cost control is structural and already in place: the model is called ONLY after eligibility passes, so every refused contact costs zero tokens, and on the shipped fixture feed that is most of them. The prompt is also bounded by construction (a template id, a locale, a channel and a handful of facts). TODO (repo owner): pick the model, set a per-request token budget and a kill switch, and report spend through `agent-observability`. |
| **P-12** Reversibility, documented exit | Covered | The `onprem` family raises rather than pretending, so the portability claim cannot be silently false (`tests/contract/test_behavioral_parity.py`); the audit trail exports to and restores from JSON Lines, so the exit is a file copy; the path is written down in `docs/onprem-migration.md`. |
| **P-13** Fair, consented marketing | Covered in the direction that applies | This service sends SERVICE notifications, not marketing, and the distinction is load-bearing rather than semantic: it asks the consent store under the `service` purpose, so a subject who opted out of marketing is still told their card was declined, and a subject who opted out of service contact is not contacted at all. It cannot be used for marketing without changing the configured purpose, which is a reviewable diff. Every send is consent-gated, frequency-capped, suppression-checked and quiet-hours-bounded, with the deciding consent id on the audit record. |

## Platform dependency rules

| Rule | Status | Control and evidence in this repo |
|---|---|---|
| **R1** Customer or PII data must go through `agent-guardrail-gateway` (redaction, injection defence, I/O filtering) | Partial | Redaction is in place everywhere data crosses a boundary, using the shared `pii-kit` with a jurisdiction selection this deployment owns (`domain/pii.py`), and the OUTPUT filter is the strongest in the fleet: a drafted body is rejected outright if it carries personal data or a figure the event did not supply. The injection surface is unusually small, because the free-text detail never reaches the model at all; only the closed fact set does. TODO (repo owner): bind a `GuardrailPort` to the `agent-guardrail-gateway` so the screening decision is the platform's rather than this repo's. |
| **R2** Any production system must depend on `agent-observability` (tracing plus immutable audit) | Partial | The immutable audit half is local and tamper-evident today. The tracing half now EMITS: `domain/outreach_service.py` opens `outreach.sweep` around a tenant feed and `outreach.evaluate` around each decision, with a fixed allowlist of structural attributes and no content, which `tests/unit/test_span_emission.py` pins in both directions. TODO (repo owner): point the managed tracer at the `agent-observability` collector so those spans and the prompt/response record land in the shared sink rather than only in this process. |
| **R3** Any RAG or grounded use case must depend on `enterprise-knowledge-base` | n/a | There is no retrieval and no corpus. A service notification is grounded in the operational event that caused it, which arrives on the request; a knowledge base would add a source of claims this service is not allowed to make. If a future scope adds one, this becomes mandatory together with P-05. |
| **R4** Any deployed agent or exposed tool must register in `agent-registry` | Partial | The agent publishes a discovery card at `/.well-known/agent-card.json`, built from the same tool table the runtime binds (`agent/agent_card.py`, `tests/unit/test_agent_surface.py`). TODO (repo owner): register the card with `agent-registry` and take the agent's identity and entitlements from it. |
| **R5** Any model or agent promoted to production must pass the `model-quality-gate` | Partial | `eval/run_eval.py --mode gate` is the client half and refuses to run off the managed profile. TODO (repo owner): register the bundle with `model-quality-gate` (see P-08). |
| **R6** Any new project should pass `architecture-validator` at intake | TODO (repo owner) | An intake action, not a code control. Record the `architecture-validator` validation reference here when the project passes it. |
| **R7** Customer-facing marketing must pass `marketing-compliance-gate` | Covered in the direction that applies | No marketing output (see P-13), but the `marketing-compliance-gate` dependency is real and load-bearing in the other direction: `marketing-compliance-gate` owns the consent and preference store, and this service asks it through `consent-preference-kit` on every single contact. There is no local consent store on any profile, and the managed adapter REFUSES when the store URL is unset rather than falling back. |
| **R8** Anything that sets `requires_human_review` must route to `human-review-console` | Covered | `ports/review_router.py` with an adapter in every profile: the offline family enqueues to the review kit's outbox (deliberately not a no-op), the managed family submits to the console over S2S, the on-premises family refuses. The API, the CLI and the agent tool all route in the same call that produced the result. The payload is redacted before the wire, and the managed router REFUSES when no console is configured rather than swallowing the escalation. `tests/unit/test_review_routing.py` and `tests/contract/test_behavioral_parity.py` are the standing gates. |

## Cross-cutting controls

| Area | Status | Evidence |
|---|---|---|
| Supply chain | Covered | Committed `requirements-dev.lock` and `requirements-gcp.lock`, installed with `--no-deps` by `make install`, CI and the Dockerfile, with the catalog commons pinned to 40-character COMMIT shas (a tag can be moved, so a tag pin lets what installs change with no diff); digest-pinned base image; SHA-pinned Actions; dependabot per ecosystem; `pip-audit` as a hard CI failure. `tests/unit/test_repo_artifacts.py` asserts each of these from inside the repo. |
| Fail-closed configuration | Covered | The profile resolves THREE states into a `ProfileChoice`: unset is NO CHOICE (never a silent `local`), an emptied value and an unknown or mis-capitalised one both raise AT IMPORT, so a process fails to boot rather than serving on a posture nobody chose. Relaxations key off the derived `exposure_profile` and the loopback bound off the derived `bind_profile`, because the two fail closed in opposite directions. Only `config.py` may read the variable; `tests/unit/test_profile_single_source.py` fails the build if a second module re-derives it, and `tests/unit/test_three_state_env_reads.py` fails it for ANY two-state environment read in shipped code, which is how a two-state read of a different variable stops being invisible. |
| Secret handling | Covered | No secret value is committed. `config/settings.yaml` and `.env.example` carry names and non-secret defaults; `.env.secrets.example` carries placeholders. Inbound and outbound credentials are deliberately distinct variables. |
| Browser boundary (`ui/`) | Covered | The client never asserts identity: every client-supplied actor, tenant, role, ACL and authorization header is discarded before forwarding (`ui/lib/embed-policy.mjs`), identity is resolved server-side (`ui/lib/identity-policy.mjs` behind `ui/lib/server/identity.ts`), and the service credential is read from the server environment so it never reaches a bundle. Every environment read behind that boundary resolves three states like the service's own: unset REFUSES a `UI_PROFILE` rather than seeding a dev persona, and an emptied `UI_PROFILE`, `UI_FRAME_ANCESTORS`, `UI_TENANT_ORIGINS` or `AGENT_API_URL` refuses rather than inheriting the unset default, the two allowlists doing so from `next.config.mjs` so a UI whose allowlist rendered empty never boots. Framing and CORS are per-tenant allowlists that refuse a wildcard; an unset tenant allowlist denies. The outbound `AGENT_S2S_TOKEN` is deliberately two-state, matching `hex_service_kit.s2s.client_headers`, because the receiver decides. Proved by `ui/tests/embed-policy.test.mjs` and `ui/tests/identity-policy.test.mjs` in the ui-gate workflow, guarded against regression by `ui/tests/three-state-env-reads.test.mjs` (which scans every shipped `.mjs`/`.ts`/`.tsx` in `ui/`, the blind spot that let a wildcard-CORS two-state read survive the whole gate), and held to the wall by `tests/unit/test_ui_surface.py` in the offline gate. N/A once `make drop-ui` has run. |
| Demonstrability | Covered | The demo is code and every narrated claim is asserted (`make demo-selftest`), the portability claim is executable and bounded (`make portability`), and the hosted check runs both on every pull request and every push to main. A claim that stops being true fails a build rather than a meeting. |
| Tenant isolation | Partial | The tenant is taken from the VERIFIED principal and never from the request body, so a caller cannot ask about another tenant's subject by naming it (`api/app.py`), and it is carried on every outbound review and every consent question. TODO (repo owner): derive object-level authorisation server-side from data tags as soon as this service gains a queryable store. |
| Decision-time integrity | Covered | No surface accepts an `as_of` from its caller. The domain takes an explicit instant, which is what makes a decision replayable, but quiet hours are evaluated against it, so a caller who could choose it could evade them; it matters most on the agent surface, where the caller is a model. `api/schemas.py` carries no such field, `agent/tools.py` takes no such parameter and `cli/main.py` offers no such flag. |

## Adopter-owned crosswalk

The mapping above is to the catalog's own principles and rules. The mapping from those to a
specific regulation, and the decision that a control is SUFFICIENT for that regulation, is
adopter-owned: it depends on the institution's risk appetite, its regulator, its licence
conditions and its existing control library. This repo does not make that claim on an adopter's
behalf, and no row above should be quoted as regulatory assurance.

What an adopter is expected to add, in their own control library rather than in this file:

- the crosswalk from each row above to their MAS TRM, CPS 234, CPS 230, HKMA or PDPA control ids;
- the risk acceptance for every row still marked Partial or TODO at go-live;
- the second-line review of the deterministic policy in `domain/`, which is bank-owned logic and
  not a vendor default to be inherited unexamined;
- the retention schedule and the legal basis for the audit trail this service writes.
